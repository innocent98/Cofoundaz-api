# SOP: Postgres test harness + typed SQLAlchemy Base

## What shipped

- Commit: `85f5689` — "test: real Postgres harness with per-test rollback + typed Base"
- Branch: `design/auth-onboarding-foundation`
- Task 1 of the Foundation & Tenancy Spine plan
  (`.superpowers/sdd/2026-08-12-foundation-tenancy-spine/task-1-brief.md`).

Replaced the scaffold's SQLite-backed pytest harness with a real-Postgres,
per-test transaction-rollback harness, and upgraded the SQLAlchemy
declarative `Base` from the legacy `declarative_base()` call to a typed
`DeclarativeBase` subclass carrying a constraint naming convention.

## Why

The scaffold's `tests/conftest.py` ran tests against a local SQLite file
(`sqlite:///./test.db`), which diverges from production Postgres in dialect
behavior (types, constraints, `ON CONFLICT`, JSON operators, etc.) and would
let schema bugs slip past tests. The project's global testing constraint is
"real Postgres, per-test transaction rollback, no SQLite." `Base` also
lacked a naming convention, so Alembic-autogenerated constraint/index names
would be inconsistent and hard to reference in future migrations.

## How

- **`app/db/base.py`**: replaced `declarative_base()` with a `Base(DeclarativeBase)`
  class whose `metadata` carries an explicit `NAMING_CONVENTION` dict
  (`ix_`, `uq_`, `ck_`, `fk_`, `pk_` patterns), per SQLAlchemy 2.0 typed style.
- **`app/core/config.py`**: added `TEST_DATABASE_URL: Optional[str] = None` to
  `Settings`, alongside the existing `DATABASE_URL` block. Optional so
  production/dev environments without a test DB configured don't fail
  validation.
- **`tests/conftest.py`**: replaced the SQLite engine/session-per-test setup
  with three fixtures:
  - `engine` (session-scoped): connects to `TEST_DATABASE_URL` (falling back
    to `postgresql://user:password@localhost:5433/cofoundaz_test`), drops
    and recreates `Base.metadata` once per test session.
  - `db` (function-scoped): opens a connection + outer transaction per test,
    binds a `Session` to it with `join_transaction_mode="create_savepoint"`
    (SQLAlchemy 2.0 feature — lets application code call `session.commit()`
    without escaping the outer transaction, via a savepoint), then rolls the
    outer transaction back in teardown. This gives true test isolation even
    if the code under test commits.
  - `client` (function-scoped): builds a `TestClient` that overrides the
    `get_db` FastAPI dependency to yield the same `db` session, so
    request-scoped DB access in a test shares the test's transaction.
- **`app/db/models/__init__.py`**: left empty (already existed from the
  scaffold) — Task 12 will populate it with model imports so
  `Base.metadata.create_all` picks up real tables. With zero models
  registered, `create_all`/`drop_all` are no-ops; the harness tests
  (`tests/test_harness.py`) exercise raw SQL only, so this doesn't block
  verification.

**Alternative rejected:** keeping SQLite for speed and adding Postgres only
in CI. Rejected per explicit project constraint (no SQLite, ever, in tests)
and because dialect-specific bugs (e.g. Postgres-only constraint naming,
JSONB, enums) would otherwise only surface in CI, not locally.
