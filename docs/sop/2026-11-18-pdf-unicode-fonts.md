# SOP: PDFs print "₦" and Yoruba letters (bundled DejaVu fonts); "A team member" in Analytics

| | |
|---|---|
| **What shipped** | Every ReportLab PDF the API renders now uses bundled DejaVu fonts, so money prints as "₦7,777.00" instead of "?7,777.00" and names keep their Yoruba marks ("Adébáyọ̀ Ọlá"). Analytics also names a member with no profile name "A team member" (SO1), never "Member". Branch `fix/analytics-pdf-naira`, PR to `develop`, not merged. No migration, no env. |
| **Date** | 2026-11-18 |
| **Found by** | The lead's every-control re-walk of Analytics wave 1 on merged develop (`cofoundaz/docs/checklist/analytics-rewalk.md`, defects D1 and D4). |

## Why
ReportLab's built-in Type 1 fonts (Helvetica, Times, Courier) are WinAnsi (cp1252) only, and U+20A6 "₦" is not in
WinAnsi. Every analytics PDF (founder, team member, accountant) printed "?7,777.00": the file a founder sends to a board or
a bank. The same limit made document exports print "?" for ₦ in legal drafts. It also made certificates, e-sign
certificates and receipts drop the dots from Yoruba vowels, or print "?". The slice C verification row checked
`%PDF` and redaction, not the currency glyph, so this got through.

## How
- **One font module:** `app/core/pdf_fonts.py`.
  - `register()` is idempotent and registers DejaVu Sans (regular, bold, oblique) and DejaVu Serif Italic. Each renderer
    calls it before building a document.
  - It maps `<b>`/`<i>` to the family.
  - `printable(text, font, fallback="?")` keeps every character the font can draw. A character outside the font (emoji,
    CJK) is reduced to its base letter, or to `fallback`, never an empty box.
- **The font files:** `app/assets/fonts/` holds DejaVu 2.37 (`DejaVuSans.ttf`, `-Bold`, `-Oblique`,
  `DejaVuSerif-Italic.ttf`), unmodified, from the official release `dejavu-fonts-ttf-2.37.tar.bz2` (sha256
  `fa9ca4d1…46e17d7`).
  - The licence ships beside them (`LICENSE-DejaVu.txt`, Bitstream Vera + public domain). It allows redistribution of
    the unmodified fonts with the notice.
  - ReportLab embeds only the glyphs a document uses (a subset). The Board pack PDF measured 44 KB live (it was
    2.4 KB with Helvetica, which is never embedded), well under the 15 MB export cap.
  - The Docker image includes them: the Dockerfile copies all of `app/`, and `.dockerignore` allows `app/` without
    excluding `.ttf`.
- **Renderers switched:**

  | File | Change |
  |---|---|
  | `app/services/analytics/render.py` | every style, footer and table grid (plain-string cells inherit the grid font) |
  | `app/services/documents/export.py` | styles + footer; `_pdf_text` now uses `printable` (the old cp1252 fold turned "₦" into "?") |
  | `app/services/documents/esign_pdf.py` | styles, footer, table labels; signature line uses DejaVu Serif Italic. Hashes, IP and user agent stay Courier (ASCII) |
  | `app/services/learning/certificates.py` | all text; `_printable` keeps Yoruba marks (drops only what the font lacks) |
  | `app/services/billing/receipt.py` | all text; company name and address through `printable` |
  | `app/services/funding/watermark.py` | the viewer label (e-mail) through `printable` instead of a latin-1 "replace" |

- **Not changed:** `app/services/finance/invoice_pdf.py` is a hand-written PDF emitter with no dependency, and is Latin-1
  only by design. It prints amounts as "NGN 1,500.00", so it never hit the ₦ problem. A client name with Yoruba marks
  still prints "?" there; embedding a TrueType font in that emitter is a rewrite, so it is listed as a follow-up. Receipts
  also print "NGN …" (`app/core/money.format_money`), unchanged.
- **D4.** Analytics `names()` and every owner, `run_by`, `created_by` and share-candidate fallback use
  `app.core.names.NAMELESS_MEMBER` ("A team member"), as Business Builder and Calendar already did.
- **Rejected:** Noto Sans. It covers more scripts, but it is split across many files and is larger. DejaVu covers
  Latin Extended Additional (Yoruba) and ₦ in one file per face.

## Verification
- `tests/core/test_pdf_fonts.py` renders a real file from each of the six renderers and reads it back with pypdf, asserting:
  - analytics `₦7,777.00` and no `?7,777`;
  - a document export "Salary ₦450,000";
  - e-sign "Loan of ₦2,000,000" and Yoruba signer names;
  - an academy certificate holder;
  - a receipt company name and address;
  - a watermark Unicode e-mail.
- It also checks font coverage and that the licence file is present.
- `tests/api/test_analytics_exports.py::test_report_pdf_end_to_end_audited_and_notified` covers the real API + worker +
  download path: `₦7,770.00` and "generated by A team member". `tests/api/test_analytics_reports.py::test_a_member_with_no_profile_name_is_a_team_member_never_member`
  covers owner, `run_by` and share candidates, and that no e-mail appears.
- Existing tests updated for the new, better behaviour: Yoruba is kept, not folded (`test_documents_export_render.py`,
  `test_certificates.py`).
- **Live:**
  - The e2e journeys `e2e/test_analytics_reports.py` and `e2e/test_analytics_exports.py` re-ran against a scratch
    server. The exports journey now asserts `₦5,000.00` in the downloaded PDF's text. All captures were re-taken, and
    both guides' bodies were refreshed from them.
  - A scratch-stack accountant PDF read "₦7,777.00" with Marketing still locked (no 4321).
- **Fast checks:** black, isort, ruff, mypy `app` (557 files), and bandit on the touched files. Bounded tests: the 3
  render suites, e-sign, data room, analytics reports + exports, billing plan gate (183 + 51 passed). The full suite is
  left to CI.

## Operate / roll back
Nothing to configure. Revert the PR to return to Helvetica: PDFs will print "?" for ₦ again. Existing stored files (old exports,
certificates) are not re-rendered. Analytics exports expire in 30 days anyway, and certificates keep the PDF they were issued with.

## Follow-ups
- `finance/invoice_pdf.py`: client names outside Latin-1 print "?". Either move it to ReportLab + DejaVu, or embed a font in the
  emitter.
- Characters outside DejaVu (CJK, emoji) still fold to "?" in PDFs; DOCX exports keep them.
